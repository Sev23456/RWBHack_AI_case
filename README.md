# MAS Pipeline

Единый конвейер на основе предоставленных аналитика, оркестратора, Backend, Web, Mobile и Angular UI.

## Запуск

Нужны Docker Engine, Compose и доступ сервера к LLM, npm/NuGet/Google/контейнерным реестрам.

```bash
cp .env.example .env
# Заполнить LLM_URL, LLM_API_KEY, LLM_MODEL
 docker compose up -d --build
 docker compose logs -f orchestrator backend web mobile tester
```

UI: http://localhost:8088. Все внутренние сервисы слушают 8000 без публикации наружу.
Для доступа с другого компьютера открыть http://IP_СЕРВЕРА:8088.
Адреса API и WebSocket в UI относительные, проходят через nginx.
Перезапуск контейнеров настроен unless-stopped. Данные сохраняются в mas-data.

Android проверяется на Linux x86_64 с доступным /dev/kvm. До первого MOBILE прогона:

```bash
docker build -t mas-android-runner runners/android
```

Образ большой: SDK, эмулятор API35 и SDK platforms35/36. Недоступность KVM, образа или требуемой SDK приводит к отказу, архив не считается готовым. На Windows/macOS запускать этот контур на Linux VM с nested virtualization.

## Рабочий маршрут

1. UI отправляет бизнес-требования через WebSocket. Фоновый прогон продолжает работу при закрытии вкладки.
2. Orchestrator вызывает analyst `/analyze`, проверяет success и передаёт data в планировщик.
3. Планировщик формирует выбранные задачи и замороженный JSON-контракт: OpenAPI, события, данные и критерии приёмки с ID. Нет фиксированного набора компонентов.
4. Каждый агент вызывает tester `/validate` напрямую после генерации. Tester собирает и запускает приложение. При отказе сборки/запуска тесты не генерируются, попытка отклоняется и агент получает обратную связь.
5. После успешного запуска tester придумывает декларативные тесты через LLM и выполняет HTTP, Chromium или Android-проверки. Сбой тестера также означает отказ. До трёх попыток по умолчанию.
6. Только tester создаёт `approved/<role>.zip` и возвращает путь с хешем контракта. Агент передаёт итог оркестратору.
7. Orchestrator ждёт точное множество выбранных ролей, распаковывает архивы и вызывает интеграционную проверку. WEB+BACKEND проверяются вместе, включая nginx API proxy.
8. Документация генерируется по фактическим файлам, требованиям и отчётам. Итоговый project.zip доступен после успешных проверок.

## API

- POST `/runs` JSON `{"text":"бизнес-требования..."}` → 202 с run_id.
- POST `/orchestrate` принимает уже готовое структурированное ТЗ → 202.
- GET `/runs`, `/runs/{run_id}` — история и статус.
- GET `/runs/{run_id}/download` — финальный ZIP, 409 до готовности.
- WS `/ws/pipeline` — первый JSON `{"task":"..."}` или `{"run_id":"..."}` для подключения к событиям.
- GET `/api/files?run_id=...` — дерево, `/api/files/content?run_id=...&path=...` — текст файла.
- У каждого агента POST `/work`; tester POST `/validate` и `/integrate`.

Сервисы агентов сериализуют собственные запросы: исходный код использует глобальные счётчики/каталоги отладки. Оркестратор выполняет один прогон за раз, компоненты внутри него идут параллельно. После перезапуска незавершённые прогоны получают interrupted, автоматического возобновления нет.

## Что проверяется

BACKEND: production Docker build, запуск с отдельным PostGIS, /health, HTTP-сценарии и схемы ответов из утверждённого OpenAPI. Внутренний проект не может менять набор методов и путей контракта. Это не формальное доказательство всех свойств бизнес-логики.

WEB: production build, nginx startup, Chromium и наличие ожидаемого текста. На независимом компонентном этапе backend ещё может отсутствовать: сетевые сценарии будут отклоняться, а не проходить на фиктивных данных. Финальная проверка запускает настоящий backend и повторяет HTTP-тесты через web proxy.

MOBILE: Gradle build и unit tests, установка APK в эмулятор, запуск процесса, отсутствие FATAL EXCEPTION и проверки видимого текста UIAutomator. Тесты мобильного взаимодействия с сервером и сложные последовательности действий пока не покрываются. Gradle wrapper возвращается в одобренный архив.

coverage.json связывает критерии с реально выполненными тестами; отсутствие evidence даёт unverified. Даже passed отражает только выполненные утверждения. Сырой отчёт сохранён в output/<run_id>/qa.

В manifest подсчитаны токены планировщика, генераторов, тестирования и документации. Оригинальный analyst не отдаёт usage, поэтому его токены явно помечены как неизвестные. Каждый отчёт агента содержит попытки и собственные счётчики. Итоговый CI содержит сборочные jobs; автоматического push в GitLab нет. После скачивания проекта пользователь отправляет его в свой GitLab штатным git push.

## Развёртывание сгенерированного продукта

В project.zip находятся выбранные backend/, web/, mobile/, contracts/, docs/, coverage.json, manifest.json, .gitlab-ci.yml и docker-compose.yml (если есть сервер/web). Скопировать .env.example в .env, задать DB_PASSWORD, выполнить docker compose up -d --build. Для Android открыть mobile/ в Android Studio или выполнить инструкции README. localhost backend для эмулятора — 10.0.2.2:8080.

## Проверки разработки

```bash
python -m unittest discover -s tests -v
python -m compileall -q common services
```

Проверки с подменёнными сетевыми зависимостями подтверждают маршрутизацию и правила отказов. Они не заменяют полный прогон с настоящими LLM, Docker и Android. Здесь эти внешние среды не были доступны.

## Границы доверия

Пайплайн предназначен для доверенной команды в изолированной VM. Tester имеет доступ к Docker socket и запускает сгенерированный код. UI и API не имеют аутентификации. Публиковать этот порт в открытый интернет без отдельной защиты нельзя. Все пути файлов ограничены каталогом прогона. В архив не включены исходные ключи, .env, node_modules и кэши.

## Проверено при сборке архива

Семь локальных тестов прошли, включая прямой цикл агент→tester→исправление, выбор BACKEND ONLY / WEB+BACKEND / MOBILE ONLY, блокировку при отказе компонента и несовпадении контракта. Проверены Python compileall и Angular ngc (TypeScript + шаблоны). Production ng build в локальной среде не прошёл из-за esbuild для Windows в исходном архиве. Docker UI устанавливает зависимости с нуля через npm ci. Реальная Docker-сборка, LLM, Android-эмулятор и интеграционные приложения здесь не запускались.
