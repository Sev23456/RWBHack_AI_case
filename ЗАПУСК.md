# Как поднять MAS Pipeline (Windows + Docker Desktop)

## Что нужно

- Docker Desktop (запущен, режим Linux-контейнеров).
- Доступ к модели Qwen через SSH-туннель (модель видна только из сети ВМ).
- ~15 ГБ свободного места: образы tester (~3 ГБ) и backend (~1,3 ГБ), плюс образы генерируемых приложений.

## 1. Туннель к модели — отдельное окно PowerShell

```powershell
ssh -N -L 4000:10.10.10.10:4000 team7@85.143.113.230 -p 10007
```

Ввести пароль team7. Окно «зависнет» без вывода — так и должно быть. **Не закрывать**, пока работает пайплайн.

Проверка (в другом окне):

```powershell
Test-NetConnection localhost -Port 4000
```

`TcpTestSucceeded : True` — туннель есть.

## 2. Файл `.env`

В папке `mas-pipeline` (рядом с `docker-compose.yml`) должен лежать `.env`:

```
LLM_URL=http://host.docker.internal:4000/v1
LLM_API_KEY=sk-ваш_ключ
LLM_MODEL=qwen3.8-27b
UI_PORT=8088
MAX_REPAIR_ATTEMPTS=3
```

Каждая переменная — на своей строке, в конце файла — перевод строки.
Если дописывать строки в конец файла без перевода строки, они склеятся
(`LLM_MODEL=qwen3.8-27bUI_PORT=8088`) и модель будет отвечать `403 Forbidden`.

## 3. Запуск

```powershell
cd "D:\ИИ-агенты\mas-pipeline-integrated\mas-pipeline"
docker compose up -d --build
```

Первая сборка — 10–20 минут (.NET SDK, Chromium для Playwright, npm). Повторные запуски — секунды.

Проверка, что всё поднялось (все сервисы `healthy`, ui — `Up`):

```powershell
docker compose ps
```

### Состав сервисов

| Сервис | Что делает |
|---|---|
| `ui` | Веб-интерфейс, порт 8088 — единственный опубликованный наружу |
| `orchestrator` | Ведёт прогон: очередь, вызовы агентов, сборка `project.zip`, интеграция, покрытие |
| `analyst` | Бизнес-требования → структурированное ТЗ |
| `planner` | ТЗ → выбор компонентов, задачи агентам, замороженный контракт |
| `backend`, `web`, `mobile` | Агенты компонентов: проектирование, сборка, цикл с tester |
| `backend-coder`, `web-coder` | Кодеры агентов backend и web: написание и исправление файлов (вызываются агентом по `CODER_URL`) |
| `tester` | Сборка и запуск компонентов в Docker, тесты, интеграция |
| `docs` | Документация по фактическому результату |

Если у агента `backend` или `web` не задан `CODER_URL`, кодер работает внутри агента, как раньше.

### Отключение компонентов

Мобильное приложение (MOBILE) **по умолчанию отключено**, пока его агент дорабатывается.
Planner по-прежнему проектирует его (контракт API и критерии полные), но задачу агенту не ставит;
в отчёте такие критерии отмечены «компонент отключён». Запрос, которому нужно *только* мобильное
приложение, сразу завершается с понятной причиной.

Включить обратно — в `.env` пустое значение, затем `docker compose up -d orchestrator`:

```
DISABLED_ROLES=
```

## 4. Работа

- UI: <http://localhost:8088> (с другого компьютера — `http://IP_ЭТОГО_ПК:8088`).
  Вкладка «Генератор» → вставить бизнес-требования → «Запустить пайплайн».
- Ход прогона виден в терминале UI. Закрытие вкладки прогон не останавливает.
- Через API:
  - `GET http://localhost:8088/runs` — список прогонов и статусы;
  - `GET http://localhost:8088/runs/<run_id>/download` — итоговый `project.zip` (409, пока не готов);
  - `GET http://localhost:8088/runs/<run_id>/report` — итоговый отчёт: задача, план, код, каждый тест,
    покрытие критериев, токены и время. Пишется и для упавших прогонов; ссылка выводится в терминале UI.
- Проверка сервисов по отдельности через curl (порты 8101–8110):
  `docker compose -f docker-compose.yml -f docker-compose.ports.yml up -d`, затем
  `scripts/test_services.sh quick` (или `full` — с прогоном агентов и оркестратора).
- Регрессия analyst на 10 эталонных запросах: `python scripts/test_analyst.py`.
- Перенос образов на сервер: `REMOTE=user@host SSH_PORT=port START=1 scripts/transfer_images.sh` (Git Bash).
- Логи агентов:

```powershell
docker compose logs -f orchestrator backend web tester
```

Прогон WEB + BACKEND занимает ориентировочно 15–45 минут. Основное время уходит на лимит
запросов к модели: в логах `429: лимит запросов, жду 60 с` — это нормально, агенты ждут сами.
Одновременно выполняется только один прогон, следующие ждут в очереди.

## 5. Остановка

```powershell
docker compose down
```

Результаты прогонов сохраняются в volume `mas-data` и переживают перезапуск.
Незавершённые на момент остановки прогоны получат статус `interrupted` — их нужно запустить заново.

Полная очистка результатов (необратимо):

```powershell
docker compose down -v
```

## Ограничения

- Проверено сквозными прогонами 2026-10-31 на реальной модели: заметки, трекер задач и каталог библиотеки
  (BACKEND + WEB) — `completed`; библиотека — все 10 критериев подтверждены тестами. Итоговый `project.zip`
  разворачивается своим `docker compose up` и работает (API, база, веб-интерфейс).
- Тексты интерфейса из запроса доходят до кода дословно (заголовки, подписи, кнопки), но генерация
  недетерминирована: тот же запрос иногда требует 2–3 попыток компонента или не проходит совсем.
- Время прогона 8–35 минут, в основном из-за лимита запросов к модели (429). Для демонстрации лучше
  иметь заранее записанный удачный прогон.
- **MOBILE** отключён (см. «Отключение компонентов»). Когда его включат, проверка Android идёт только на
  Linux x86_64 с `/dev/kvm` и образом `docker build -t mas-android-runner runners/android`.

## Если не работает

| Симптом | Что делать |
|---|---|
| В UI «Ошибка WebSocket соединения» | `docker compose ps` — orchestrator должен быть `healthy`; `docker compose logs orchestrator` |
| Прогон падает сразу с ошибкой LLM / `All connection attempts failed` / «Модель (LLM) недоступна» | Туннель закрыт — проверить окно из шага 1 |
| «Компоненты не приняты тестировщиком …» | Причина по компоненту — в той же строке; подробно — `/runs/<run_id>/report`, раздел 4 |
| «Запрос требует только отключённые компоненты» | Запрос только про мобильное приложение, а MOBILE отключён (см. «Отключение компонентов») |
| `403 Forbidden` от модели | Проверить `.env` (склеенные строки, неверный ключ) и выполнить `docker compose up -d` |
| `Analyst rejected requirements` | Модель трижды выдала невалидную структуру; переформулировать требования подробнее и запустить снова |
| Прогон висит в `running` очень долго | `docker compose logs -f backend web tester` — смотреть, на каком шаге агенты |
| Нужно пересобрать после изменения кода | `docker compose up -d --build` |
